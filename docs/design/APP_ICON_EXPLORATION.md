# CPU Killer 应用图标探索

> 什么时候该读：重新设计、选择、精绘、接入 CPU Killer 应用图标，或排查进程表 / Finder 仍显示旧图标（粉底黑叉）前**必读**。不读会把方向探索板的某一格直接当成终稿，或把系统还在吐旧图误判成母版没换、去改菜单栏双环。

## 当前状态

- 2026-08-30 的三轮九宫格和第 4 格变种板均未通过用户审美验收，仅保留作失败参考，不得选格接入。
- 用户要求继续后，已改为三张黑白几何结构稿；用户已确认第 5 格白底独立主图并完成正式接入，菜单栏模板仍未改动。
- 九宫格只用于比较方向，不是生产主图；选定后必须按「方向板 → 精确裁格 → 独立 1024 主图 → 小尺寸检查 → 用户确认 → 接入」继续。

## 设计基线

- 产品名固定为 **CPU Killer**；应用图标使用一个主符号，不放文字、标签、设备框、预裁圆角或外部投影。
- 主图使用方形、不透明、满画布背景；主体要从用户熟悉的现实原型出发，缩小到 48px / 24px 仍保留明确轮廓。
- 主应用图标与菜单栏双环模板是两套资产：双环只表达菜单栏上的 CPU / 内存状态，不自动成为应用图标的最终构图。
- 同类 Mac 菜单栏工具的公开页面普遍强调仪表盘、读数、折线图和泛系统监控；本产品先用清晰、克制的 CPU 几何轮廓建立识别度，不把图标做成高饱和海报或被动监视器图表。

## 第二轮探索要求

本轮排除第一版的芯片、X、骷髅、炸弹、剪刀、断路器、保险丝、停止按钮、双环等主体语汇；每格仍必须只有一个核心隐喻，并使用不同视觉路线。候选方向为：日蚀、刹车踏板、拉链、橡皮擦、相机光圈、马蹄磁铁、锚、扫帚、门闩。

第二轮实际图板使用了：日蚀、刹车踏板、拉链、橡皮擦、相机光圈、马蹄磁铁、锚、扫帚、门闩。图板中若有模型把单一物件画成附带结构，后续选格精绘时只保留主轮廓，不把附带场景当作设计不变量。

第三轮硬约束：九格都以可识别的 CPU / 处理器芯片为唯一主角；允许探索正面芯片、俯视芯片、核心晶圆、插槽、散热结构等不同 CPU 视觉原型与视觉路线，但不允许用其他物件替代 CPU 主体，也不把文字、X、骷髅或危险符号当作主焦点。

## 第 4 格变种

- 来源：第三轮图板第 4 格，主题为「硅片 / 晶圆里的单个 CPU 芯片」，视觉路线为印刷拼贴。
- `Locked`：CPU / 处理器芯片仍是唯一主焦点；保留硅片或晶圆作为同一母方向的来源原型；保留有限套色、印刷质感和强轮廓；不加入文字或危险符号。
- `Explore`：背景色、芯片外轮廓、内部核心图形、芯片与晶圆的比例、旋转角度、印刷纹理密度和色彩关系。
- 变种板仍只是比较稿；用户选定变种后，必须再裁出对应格并生成独立 1024 主图。

## 失败复盘（2026-08-30）

- 第一至第三轮方向板，以及第 4 格变种板，均未通过用户审美验收；不得继续沿用这些图板的材质、纹理或构图作为终稿来源。
- 共同问题是把 CPU 画成写实电子零件或霓虹海报：引脚、晶圆网纹、金属高光、渐变和 AI 噪点抢过了 CPU 的主轮廓，结果不像 Apple 应用图标，也没有形成干净的品牌标志。
- 生成策略的问题是同时强塞高饱和背景、印刷质感、3D、故障、发光等效果；九格看似不同，实际只是同一套 AI 贴纸换皮，不能作为有效的品牌方向比较。
- 下一轮先禁用写实芯片、晶圆纹理、金属 / 玻璃 / 3D、荧光光效、套色噪点和复杂引脚细节；优先用确定性矢量几何重画一个 CPU 轮廓，只保留少量颜色和一个清晰的内部识别点。未得到新的视觉偏好前，不再继续生成同类九宫格。

## 记忆点与反扫码约束（2026-08-30）

- 黑白结构稿未通过审美验收：同心方框、中心定位块和四向缺口组合成了系统扫码器 / 定位框的视觉语法，不能继续作为主方向。
- `Locked`：CPU / 处理器芯片仍是唯一主体；必须有一个非对称、动作性的结束特征，让人记住 CPU Killer，而不是普通系统监视器或扫码器。
- `Explore`：斜切断口、熔断缺口、受压核心等动作语汇，以及一处有限的强调色；继续保持扁平几何，不引入写实材质、噪点、3D、文字或完整 X。
- 后续比较稿必须先通过“缩小后仍不像扫码器、仍能认出 CPU、仍有一个独特动作记忆点”三项检查。

## 黑白几何结构稿（2026-08-30）

- 三张稿均以 CPU / 处理器芯片为唯一主体，只使用黑白几何形状；差异集中在主体是实心芯片、线框芯片还是切角芯片。
- `Locked`：CPU 轮廓、四向识别缺口、单一内部核心；禁止纹理、渐变、材质、3D、发光、文字和 X / 骷髅等危险符号。
- `Explore`：外轮廓圆角或切角的比例、核心形状、留白与黑色面积；用户确认结构后再做有限配色，并单独验证 180px / 48px / 24px。
- 结构稿仍不是生产主图；用户确认后才生成独立 1024 主图。

## 第 5 格白底精绘接入裁定（2026-08-30）

- 用户明确要求将 `direction-05-pressed-chip-white-1024.png` 设置为正式 App icon，并特别要求主体居中。
- 该候选的包围盒几何中心偏移为 `x=5px, y=7px`（约 `0.7%`），左右与上下边距差均低于 `2%`，按光学居中验收成立；主体最长边约占 `83.6%`，保留其视觉重量，不额外缩小一圈。
- 正式接入必须同时更新分层 `AppIcon.icon` 和旧系统兜底 `AppIcon.appiconset`，禁止只换一条资源链；菜单栏双环模板继续保持独立、不随 App icon 改动。

## 第 5 格正式接入记录（2026-08-30）

- 正式主图：`design/app-icon/AppIcon-1024.png`；分层图标使用同一张白底 PNG 图层 `CPUKiller/AppIcon.icon/Assets/chip-pressed-white.png`，移除旧的 X 标记图层，不增加外部投影。`AppIcon.icon/Assets/x-mark.svg` 是换图前留下的废文件，正式图层不再引用；看见粉底黑叉不是这份废文件又生效了。
- **进程表仍显示粉底黑叉**：安装包和 Finder 已是白底芯片后，名单仍可能是上一版。根因是系统按「还是原来那个应用」缓存图标，监视器自己这次运行也把第一次问到的图记下；覆盖安装若没先删掉整个应用文件夹，更容易发生。不要重做母版、不要把 X 加回图层。权威口径与禁令见产品契约「应用图标」。
- 旧系统兜底：已由正式主图重新生成并覆盖 `CPUKiller/Assets.xcassets/AppIcon.appiconset/` 的 macOS 全尺寸资源；`CPUKiller/Assets.xcassets/MenuBarIcon.imageset/` 未改动。
- 构图验收：包围盒中心偏移 `x=5px, y=7px`，左右/上下边距差均低于 `2%`；最长边约占 `83.6%`，略高于严格默认阈值但符合简单主体的视觉重量裁定。
- 小尺寸验收：`180px`、`48px`、`24px` 预览均通过明暗跨度检查；Release 构建、安装和 Finder 实际图标核对已完成，主体显示居中。
